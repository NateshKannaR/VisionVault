# VisionVault — Evaluation Report

Every number in this report was measured. Nothing here is estimated, projected, or
hand-written. The report is regenerated by `node eval/generate-report.js` from the JSON
files that the evaluation runs leave in `eval/results/`; if those files are absent the
generator refuses to produce a report at all.

## How these numbers were produced

**AUTOMATED** — `node eval/run-full-eval.js`

A real Chrome window is launched and `extension/` is installed unpacked, exactly as a user
would install it. The evaluation then calls the extension service worker's own
`scanAndRedact()` for each fixture tab, so the figures come from the shipped pipeline:
DOM scan across all same-origin frames, UltraFace ONNX, Tesseract OCR, region merge, and
OffscreenCanvas redaction. Ground truth is read from each fixture's `data-gt-*`
annotations using the elements' real rendered geometry in the live layout, re-read
immediately before every scan. The redacted PNG that the pipeline returns is decoded and
its pixels are sampled inside every ground-truth region, so the leak check is a pixel
measurement rather than bookkeeping.

## How each metric is defined

**PII recall** — of the regions a fixture annotates as sensitive, the share covered by at
least one redaction box. Matching uses *coverage of the truth region*, not IoU: a mask
larger than the region still hides the data, and penalising it would reward masks that are
tight enough to leak at the edges.

**PII precision** — a redaction counts against precision only when it hides an element the
fixture explicitly annotates as safe (`data-gt-safe`). Boxes that overlap nothing annotated
are neither rewarded nor penalised, because the fixture makes no claim about them.

**Redaction tightness (IoU)** — mean intersection-over-union of each matched mask with the
region it covers. This is where over-redaction shows up: a mask that blacks out half the
page would score perfect recall and poor IoU.

**Pixel leaks** — the returned PNG is decoded and compared, pixel by pixel, against an
unredacted reference capture taken by the harness. Inside each ground-truth box, the
reference's median luma gives the local background; every pixel differing from it by more
than 35 is *ink* — the pixels that carry the information. A region leaks when more than 2%
of its ink is byte-for-byte unchanged in the redacted frame, i.e. was never painted over.

Comparing against the reference is what makes this a measurement rather than a proxy. The
obvious alternative — "what fraction of the box is black?" — punishes a tight mask for the
harmless margin around it and rewards a mask so large it swallows the page. It also cannot
score mosaic mode at all. This test is mode-agnostic: a blur fill changes the pixels too.

As a further guard against a trivially perfect score, safe regions are sampled as well: if
the whole frame were blacked out the leak count would be zero but the image would be
useless to the planner, so the runner records how many safe regions remain legible.

**Visual-context recall / role accuracy** — of the elements a fixture annotates as
interactive, the share the agent tagged, and of those, the share given the right role.
This is the metric for how faithfully the sanitized payload describes the screen.

**Mark ID stability** — the same page is scanned repeatedly and the sets of element IDs
compared. IDs are hashes of each element's identity and document-space geometry, so an
action planned against one scan still resolves on the next.

## Reproducing this

```bash
# optional: start the planning server (without it the client-side planner is used)
cd server && pip install -r requirements.txt && python main.py

# from the repository root
npm install --no-save puppeteer-core
node eval/run-full-eval.js --repeats 3
node eval/generate-report.js
```

A real Chrome window opens and drives itself; leave it in the foreground, since
`captureVisibleTab` only captures the foreground tab. Set `VV_CHROME` if Chrome is not at
the default install path. `node eval/diagnose.js <fixture.html>` prints one scan's full
stage-by-stage trace when a number needs explaining.
